# CM00-R3 正式实验报告：非下降路径猜想的反例搜索

运行日期：2026-09-08  
状态：完成；独立审计通过

## 1. 结论

R3 找到了同时否定 P1“即时方向猜想”和 P2“非下降路径猜想”的稳健反例。

可靠反例集中在 `5 状态 + 3 消息 + 3 类别` 空间：

- 360 个 P1 原始反例，消息/标签同构去重后为 60 个；
- 180 个 P2 原始屏障起点，同构去重后为 30 个；
- 全部 P1 反例在 `α=0.25` 和 `α=0.5` 下重复；
- 全部 P2 屏障在两种平滑下重复；
- 最强即时负信用为 `-0.102165`（`α=0.5`）和 `-0.169460`（`α=0.25`）。

因此，C2 的强版本不能被封账：当多个消息已经占据旧语义，而任务需要产生新的输出类别时，至少一个消息必须被重新赋义；改写会在当前 receiver 下先变差，但 receiver 适配后变好，而且不存在零损失绕行路径。

## 3. 最小机制证书

选择使用全部三个类别、全部三个消息的代表性反例：

`task = (0,1,2,0,1)`

当前编码：

`S = (0,1,1,2,1)`

目标编码：

`S' = (0,1,2,0,1)`

| 指标 | 当前编码 | 目标编码 |
|---|---:|---:|
| 准确率 / `A_code` | 0.8 | 1.0 |
| `I(Y;M)` | 0.970951 bit | 1.521928 bit |
| 最优交叉熵 | 0.381909 | 0 |

当前 receiver 将消息语义解释为 `(0,1,0)`：消息 0 和消息 2 都表示类别 0，类别 2 没有独立消息语义。目标协议必须把其中一个“重复的 0 码”改造成类别 2。

即使穷举全部 `3!=6` 种消息排列，最佳对齐仍然需要暂时破坏一个旧码义。

## 4. 机制解释

二消息—二类别任务中，可以通过保持原有码义逐步细化分区，因而前两轮总能找到非下降路径。

三消息—三类别反例中，当前协议已经把有限消息槽位全部占满，却有两个消息表达相同旧语义。要生成缺失的类别 2，系统必须完成一次“码义再分配”：

1. sender 先把某组输入改送到待复用消息；
2. 当前 receiver 仍按旧语义解释该消息，因此损失上升；
3. receiver 更新消息语义；
4. 新区分开始兑现，整体性能超过原协议。

这是一种比笼统“信用成熟”更具体的机制：**有限槽位中的码义复用屏障**。
