# CM05：训练损失能否选出跨初始化更易学的编码

## 可证伪问题与本轮证据联系

CM04 表明，在同样充分的编码中，预先指定的数值对齐编码在固定预算下相对更易学习；但没有说明不预先给出这种编码时，训练反馈能否帮助选择它。

本轮问题：**仅用少量初始化下的任务 BCE 对事先生成的有限编码池排序，选中的编码是否在未参与排序的新初始化下优于不看损失的固定随机基线？**
若只在排序初始化上好、换初始化优势消失，则“这种评分可稳定指导编码选择”的假说在本轮失败。该比较不会用结果回选评分种子或调整候选池。

本轮是受约束的编码搜索/选择诊断。候选被外部限制为双射，完整训练表用于损失计算，充分性由这个限制保障；它既不是从不充分消息开始的自主协议形成，也不是学得 sender，更不能把有限候选搜索称为完整协议空间搜索。

## 任务与信息边界

- 三个固定玩具条件 j=0,1,2。公开输入标识 x=0..15，q=0,1，r=0..15，完整 512 训练行，按 q、x、r 升序排列。
- 任务生成器用 NumPy PCG64 seed=85001+j 各抽一次 permutation(16)，定义隐藏映射 h_j(x)。答案 y=(h_j(x)+r) mod16，以四位表示；h_j 对两个 q 相同。
- 生成器单独写入训练 x,q,r,y，h_j 只写入封存的生成审计文件。排序/候选模块不得读取 h_j、V、其逆映射或数值对齐编码；不得从 y,r 显式反推它们，候选只能由下面的种子规则产生。
- 任务生成具有任务语义，排序器只调用通用 BCE 训练流程；承认训练 y,r 本身包含可推导的语义，不能仅凭文件名宣称不存在任务监督。
- 全表是训练域，不设伪装的留出标签；未参与排序的仅是后续初始化。结果只能称为跨初始化复核，不能称为测试泛化或跨任务族确认。

## 候选冻结与无反馈对照

- 每个条件 j 的唯一候选池由 PCG64(seed=86001+j) 连续调用 permutation(16) 共 16 次产生，候选 c_i:x→m，i=0..15；对两个 q 使用相同映射。
- 不加入 h_j、其逆映射、CM04 E0、CM02/CM03 映射或任何语义引导候选。随机抽到特殊映射、重复映射或候选相同均保留记录，不重抽。
- 候选对输入状态双射，全消息使用均衡；它是外部提供的充分编码支架。三条件全部候选和所有初始化在第一次评分训练前锁定。
- 无反馈基线固定为池内 c_0，不读取任何损失选择基线。即使它恰好最好，仍保留；若选中编码也是 c_0，确认阶段照常运行两个相同编码分支，差值为零，不改选其他基线。

## 两阶段预算与冻结算法

全部使用 CM04 的 bit 输入布局与 22→64→64→4 ReLU MLP，PyTorch 2.2.2、NumPy 1.26.4、float32、CPU 单线程。输入消息由候选作用于 x 产生，decoder 只见消息、q、r，不见 x、h 或 V。
Adam 统一从空状态重置，lr=0.001、betas=(0.9,0.999)、eps=1e-8、weight_decay=0，无调度/裁剪；每支恰好 100 个全批次更新，每步 512 行。

1. **排序阶段**：初始化 seeds 90..94。每个条件内，每个种子的初态在所有 16 候选间完全配对。评分为各候选五个种子的 BCE100 算术均值；选最低者，浮点数完全相同时选较小候选索引。不使用准确率或曲线中间最优步破并列。
2. **锁定选择**：写入全部候选评分、入选索引与选择哈希后，才启动下一阶段。不得观察确认种子的训练表现再重选。
3. **跨初始化复核**：seeds 120..149，共 30 个，与 CM04 及本轮排序种子不重叠。每个条件、每个种子，用同一新初态配对训练选中候选与 c_0；不复用排序阶段权重。

排序 3×16×5×100=24,000 次更新；复核 3×2×30×100=18,000 次，总计 420 分支、42,000 次全批次更新。正式运行与独立产物审计共≤60 分钟、RSS≤4 GiB。不得追加候选、步数、种子或预算。

## 冻结主判据

对复核阶段每个条件 j、每个种子 s：

- D_loss=BCE100(c_0)−BCE100(selected)；
- D_acc=Acc100(selected)−Acc100(c_0)。

**唯一主要通过规则：三个条件中每一个，都至少 24/30 个复核种子同时满足 D_loss≥0.01 且 D_acc≥0.05。** 不以条件间平均数补偿失败，不用排序阶段收益或损失单项替换联合规则。
